## 1. Problem

A voice message reaches the bot, gets "Transcribing your voice message…" and a queued job, and then nothing happens: no worker handles the `transcription` or `notification` queue, and the worker logs "No job handler is registered". S5 builds the worker side of the voice path: the transcription job (download, real size and duration checks, transcription, extraction, one task in one transaction), the notification job (the ack edited to the result or a failure text), the recovery sweep, the three `Transcriber` adapters, and the per-role composition root.

S5 does not change the bot's behaviour (S4; it touches two S4 files: `application/replies.py` gains the S5 texts, and the token shape check moves from `settings/bot.py` to a shared module), the API (S6), the dashboard (S7) or `docker-compose.yml` and the Dockerfiles (S8). Failed voice jobs stay out of the dashboard (S6-D3, umbrella Z7).

### 3.2 The failure taxonomy as built

Each row names who raises, whether the use case retries, and the text of 3.6. "Transient" means `TransientTranscriptionError` (or a download error): the use case retries while `attempt < 5` and records `transient_exhausted` at attempt 5.

| `failure_kind` | Raised by | Retry |
|---|---|---|
| `too_large` | `VoiceFileTooLargeError` from the download (the source caps declared and streamed bytes at `MAX_VOICE_BYTES`, S4-Z8) | no |
| `too_long` (new, W1) | the duration summed from the Opus packets (each packet's TOC byte gives its frame size and count, RFC 6716; the granule position is not trusted, because a crafted file can claim 5 s for 10 MB) exceeds `MAX_VOICE_SECONDS + VOICE_DURATION_TOLERANCE_SECONDS` (121 s): Telegram's `duration` is a whole number declared by the client, so a 120.4 s note that the bot accepted is not refused here | no |
| `unsupported_audio` | `UnreadableAudioError` from the duration parser (not Ogg, no `OpusHead`, a second `OpusHead` (chained streams), a truncated page or packet, no audio packet); OpenAI 400 (except `param == "model"`: `provider_unavailable`), 413, 415; whisper-server 400 (except the missing-`file` body, a code fault: `internal`) and 500 whose body says `FFmpeg conversion failed` (W3) | no |
| `empty_transcript` | the adapter's text is empty after stripping, or (whisper) consists only of non-speech markers: bracketed or parenthesised spans such as `[BLANK_AUDIO]`, `(silence)`, `[Music]`; `MessageText.parse` raising `EmptyMessageError` (no letter or digit) | no |
| `transcription_timeout` | whisper-server `httpx.ReadTimeout` or the adapter's own 300 s wall clock (the adapter converts its `TimeoutError`); the expiry of the use case's own 400 s budget (3.3); Celery's soft time limit (3.3) | no |
| `provider_unavailable` | `UnavailableTranscriber` (provider `openai`, empty key); OpenAI 401, 403, 404 (`model_not_found`, a configuration fault, W4), a 400 whose `param` is `model`, and a 429 whose `code` or `type` is `insufficient_quota` | no |
| `transient_exhausted` | at attempt 5: OpenAI `APITimeoutError` or the adapter's own 30 s wall clock (S5-D1; the adapter converts its `TimeoutError` to `TransientTranscriptionError`), `APIConnectionError`, a rate-limit 429, 408, any status ≥ 500; whisper-server connect errors (not started or loading), connect, pool and write timeouts, read/write/protocol errors, 499, 503, other 5xx; `VoiceFileUnavailableError` from the download | yes, delays 2, 4, 8, 16 s |
| `internal` | any other exception from step 2 of 3.3, except the injected interrupts (a bare `TimeoutError` that is not the budget's included); an OpenAI result that is not a `Transcription` with a `str` text, a whisper 200 whose body is not `{"text": str}`; any unmapped status | no |
| `stuck` | `exhaust` after the ceiling (crash loop) | no |

A database or broker error during an attempt is not mapped: the unit-of-work steps of 3.3 sit outside the mapping `try`, so the error leaves the use case, the task body logs its class name only and acknowledges, the row stays `processing`, and the lease and the sweep retry it as the next attempt (W7). The engine is built with `hide_parameters=True`, so a SQL error's text carries no transcript (W17). Celery never retries (`self.retry` is never called).

### 3.3 `TranscribeVoiceJob` (S5.3)

Constructor ports: `uows`, `create: CreateTasksFromMessage` (for `within`; built with the same extractor, `RegisterOrGetUser` and clock), `files: VoiceFileSource`, `transcriber: Transcriber`, `extractor: TaskExtractor`, `notifier: UserNotifier` (the retry edit only), `queue: JobQueue`, `publisher: EventPublisher`, `clock: Clock`, `interrupts: tuple[type[BaseException], ...]`. Two methods: `execute(job: TranscriptionJob, progress: AttemptProgress) -> TranscribeResult` and `time_out(voice_job_id, attempt) -> TranscribeResult` (the soft-limit backstop, below). `AttemptProgress` is a small mutable holder the use case fills with the claimed attempt; `TranscribeResult` is `Done | Failed | Retrying | Waiting | Stale | Dropped`, for logs and tests.

```
1  uow A: claim(id, now) ; commit
     Claimed(job)          → progress.attempt = job.attempts ; continue
     AlreadyFinished       → return Dropped
     LeaseLive(n)          → enqueue(TranscriptionJob, delay = max(n, 1)) ; return Waiting   (W15)
     CeilingReached        → uow: exhaust(id, now); commit; if it returned a row: enqueue NotificationJob(failed)
     JobMissing            → log ; return Dropped
2  no session open; the mapping try covers this step only; budget = asyncio.timeout(ATTEMPT_BUDGET_SECONDS = 400):
     audio   = files.fetch(job.file_id, max_bytes=MAX_VOICE_BYTES)        (download ≤ 30 s, S4 adapter)
     seconds = opus_duration_seconds(audio) ; > 121 → TOO_LONG
     result  = transcriber.transcribe(audio)                               (the adapter's own 30 s / 300 s)
     text, cut = MessageText.parse(result.text).bounded(TRANSCRIPT_MAX)   (S5-D2; a cut is logged)
     extraction = extractor.extract(text)                                   (≤ 30 s, never raises)
3  uow B: lock_attempt(id, attempt)  → None: stale attempt, roll back, return Stale
          create.within(uow, user_id=job.user_id, ref=job.ref, kind=MessageKind.VOICE,
                        text=text, extraction=extraction)
            CreatedMessage(message) | DuplicateMessage(message_id)  → message id
          complete(id, attempt, message_id, transcriber.provider, now) ; commit → events
   publish_events(publisher, events) ; enqueue NotificationJob(done)
```

Failure paths, each after the step that raised and with no session open across a slow call (L2):

- Final kind: uow `fail(id, attempt, kind, transcriber.provider, now)`; commit; enqueue `NotificationJob(failed)`. `fail` returning `None` means a newer attempt owns the row: drop.
- Transient, `attempt < 5`: when `attempt == 1` and `ack_message_id` is set, `notifier.edit_message(..., RETRYING)` first, its error logged and ignored (S5-D4); then uow `requeue(id, attempt, now)`; commit; then `enqueue(TranscriptionJob, delay=retry_delay_seconds(attempt))`. The edit runs while the row is still `processing` and leased, so no copy can claim the next attempt and finish before it; the retry edit can never overwrite a result edit.
- Transient, `attempt == 5`: as a final kind with `transient_exhausted`.
- The budget's expiry (`budget.expired()` on the use case's own `asyncio.timeout` object): final `transcription_timeout`. A `TimeoutError` that is not the budget's is `internal`; each adapter converts its own wall clock (3.8).
- An exception of a type in `interrupts`: re-raised untouched. Any other exception from step 2: final `internal`, logged with its class name only (no chat text in logs). Exceptions from the unit-of-work steps leave the use case (W7).
- An enqueue failure after a commit is logged; the stamped `last_enqueued_at` lets the sweep repair it (460 s for transcription, 120 s for notification).

`DuplicateMessage` in uow B cannot arise from S5's own writes (message, task and `done` commit together); it is handled by completing the job with the existing message id, so a manual or future path cannot wedge a job.

**Time limits.** The task is declared `soft_time_limit=420`, `time_limit=450`. The attempt budget of 400 s (download 30 + provider 300 + extraction 30 + writes) is the primary deadline because it is cooperative: Celery's soft limit is a signal that the exploration showed can be swallowed by an asyncio callback or rewritten by S4's `except Exception` adapters (W5). The soft limit stays as the backstop: the task function catches `SoftTimeLimitExceeded` (imported from `billiard.exceptions`, the class Celery re-exports) from `run_async(execute(...))` and, when `progress.attempt` is set, runs `run_async(use_case.time_out(job.voice_job_id, progress.attempt))`, which writes `fail(..., transcription_timeout, ...)` (guarded by the attempt) and enqueues the notification within the 30 s left before the hard limit. Before the claim committed there is nothing to record: the task acknowledges, and a claimed-but-unrecorded row is the sweep's. The extractor is opened with `interrupts=(SoftTimeLimitExceeded,)` (S9-Y10), and so is the use case. A hard kill leaves the row `processing`, acknowledged; the sweep repairs it.

### 3.4 `NotifyUser` (S5.3)

Ports: `uows`, `notifier`, `queue`, `clock`. `execute(job: NotificationJob) -> NotifyResult`; `NotifyResult` is `Finished(outcome) | Deferred | Retrying | NotDue | Dropped`, where `outcome` is the stored `NotificationOutcome` (edited, replied, blocked, given_up).

```
1  uow: begin_notification(id, now)
     NotificationStarted(row)        → read the text inputs in the same transaction (below); commit
     NotificationNotDue(n)           → commit; enqueue self, delay = max(n, 1); return
     NotificationCeilingReached(row) → finish_notification(GIVEN_UP); commit; log; return
     NothingToNotify                 → commit; return
2  text = notification_text(row, message, task)    (pure, application/replies.py)
3  send, no session open:
     ack_message_id set → edit_message(chat, ack, text)
         MessageGoneError → send_reply(chat, text, reply_to=message_id) → REPLIED
         success          → EDITED          ("message is not modified" is success in the adapter)
     ack_message_id NULL (S4-Z2) → send_reply(...)                           → REPLIED
4  uow: finish_notification(outcome); commit
```

- `RecipientBlockedError` → finish `BLOCKED` (quiet success).
- `RetryAfterError(s)` → uow `defer_notification(id, now + s, now)`; commit; enqueue self with `delay = s` (the queue clamps at 600 s; an early copy meets `NotificationNotDue(remaining)` and re-enqueues without spending an attempt). The attempt that met the flood wait stays counted (S2's `begin_notification` counts at the start), so five flood waits in a row end `given_up`.
- `NotificationError` or any other exception → if `row.notify_attempts == 5`: finish `GIVEN_UP` with the class name logged; else enqueue self with `retry_delay_seconds(row.notify_attempts)`.

Text inputs: for `done`, the message (`messages.get(row.inbound_message_id)`, for `degraded`) and its task (`tasks.list_for_message(...)`, the first by position); for `failed`, `row.failure_kind`. The text follows the row, not the payload: a row's terminal state is absorbing, so a mismatch is logged and the row wins (the payload's `status` stays a defensive check, umbrella 3.6).

`notification_text`:
- `done`, task present: `task_created_text(title, degraded)`; with provider `fake` the first line ends with ` (demo mode)`.
- `done`, no task left (the user deleted it, Z14): `TASK_CREATED_NO_TITLE`, plus `DEGRADED_LINE` when degraded; no demo suffix, because there is no title to mark.
- `failed`: the text of the kind (3.6).

### 3.5 `RecoverStuckVoiceJobs` (S5.3)

Ports: `uows`, `queue`, `clock`. One uow runs `stamp_stale_processing`, `stamp_stale_queued`, `stamp_unnotified` (each at most 100 rows, `FOR UPDATE SKIP LOCKED`, stamped in the same statement), commits, then enqueues `TranscriptionJob` for every stamped processing or queued id and `NotificationJob(status)` for every unnotified row. Enqueue failures are logged; the stamped rows wait one more threshold. The sweep never changes `attempts`; exhaustion is the claim's. Two concurrent sweeps (the start-up copy and a beat tick on the two notify children) are safe through `SKIP LOCKED`.

### 3.7 Settings and the pre-flight (S5.1, S5.4)

- `TranscribeWorkerSettings(WorkerSettings, TranscriptionSettingsMixin, ExtractorSettingsMixin)` adds `openai_transcription_model: str = "gpt-transcribe"` and `whisper_server_url: HttpUrl = HttpUrl("http://127.0.0.1:8178")` (the dev value of umbrella 3.7; Compose overrides it in S8). These fields stay out of `TranscriptionSettingsMixin`, which the bot also inherits, so the bot never validates them. `.env.example` changes `OPENAI_TRANSCRIPTION_MODEL` to `gpt-transcribe` (S5-D3).
- `WorkerSettings.telegram_bot_token` keeps optional and gains the bot's shape check through a shared `validate_bot_token` (moved from `settings/bot.py`): a malformed token stops the worker with exit 2 naming `TELEGRAM_BOT_TOKEN` instead of crashing a child at `Bot(...)` (W13). An absent token stays one warning (S3-Y1).
- `load_worker_settings()` in `entrypoints/worker/settings.py` reads the role, then loads `TranscribeWorkerSettings` for `transcribe` and `WorkerSettings` for `notify`. The launcher, `worker_init`, `worker_ready` and `start_child` all call it, so the launcher's check and the `worker_init` pre-flight validate the same per-role model: an unknown `TRANSCRIPTION_PROVIDER` or `TASK_EXTRACTOR` or a malformed `WHISPER_SERVER_URL` exits 2 with the variable's name; a notify worker ignores them all. The pre-flight connects nothing (no `/health` probe): a stopped whisper-server becomes retries and `transient_exhausted`, never a refused start (umbrella section 9).
- `worker_ready` logs the role, the provider and the extractor (umbrella 3.6 "each worker logs them at start") and, for the notify role, sends the start-up sweep. The warnings for `openai` with an empty key and for a keyless `claude` come only from the child factories (`open_transcriber`, `open_extractor`), one per child start.

### 3.8 The `Transcriber` adapters and the factory (S5.2)

`open_transcriber(settings)` is an async context manager like `open_extractor`; the SDKs are imported only on their branch.

Every adapter owns its timeout and wall clock (W16): the port is `transcribe(audio) -> Transcript`, so the use case never switches on the provider.

- `fake` → `FakeTranscriber`: returns `[demo transcript] Please remind me to call the supplier tomorrow morning about the invoice.` for any audio; provider `fake`.
- `openai`, empty key (`openai_transcription_unavailable`) → `UnavailableTranscriber`: every call raises `TranscriptionError(PROVIDER_UNAVAILABLE)`; provider `openai`; one warning at start. The SDK constructor is never reached (it raises on an empty key).
- `openai` → `AsyncOpenAI(api_key=<key stripped>, base_url="https://api.openai.com/v1", max_retries=0, timeout=30, http_client=DefaultAsyncHttpxClient(follow_redirects=False))`, closed on exit. `OpenAITranscriber.transcribe` calls `audio.transcriptions.create(file=("voice.ogg", audio), model=<setting>)` inside `asyncio.timeout(30)`; that wall clock's `TimeoutError` becomes `TransientTranscriptionError` (S5-D1), and the SDK errors map per 3.2. A result that is not a `Transcription` with a `str` text is `internal`; a blank text is `empty_transcript`.
- `whisper_server` → `httpx.AsyncClient(base_url=str(settings.whisper_server_url), timeout=httpx.Timeout(connect=5, read=300, write=60, pool=5), follow_redirects=False)`, closed on exit. `WhisperServerTranscriber.transcribe` posts `/inference` with `file=("voice.ogg", audio, "audio/ogg")`, `response_format=json`, `temperature=0`, inside `asyncio.timeout(300)`, whose `TimeoutError` becomes `TranscriptionError(TRANSCRIPTION_TIMEOUT)`, and maps per 3.2. No `prompt`, no `temperature_inc` (the server's default fallback stays on: it trades determinism for fewer repetition loops), no `language` field: the server's `-l auto` decides (umbrella 3.1, D-09; S8 starts the Compose service with it). The body's `text` is stripped; non-speech-only text is `empty_transcript`.
- Each adapter catches only its own SDK's or httpx's exception types and its own wall clock, so an injected interrupt passes through.
- The `openai`, `httpx2`, `httpx` and `httpcore` loggers stay at WARNING (no chat text and no per-request lines in logs, as S9).

### 3.9 The worker composition root (S5.4)

`WorkerContainer` owns one `AsyncExitStack`; `start_child` builds it on the child's loop with `loop.run_until_complete(build(container))`, every resource registered the moment it exists, and `aclose()` closes the stack (LIFO) before the existing job-queue, Redis and engine steps. Nothing connects during the build (`worker_proc_alive_timeout` 30 s); SDK imports and client construction took about 0.6 s in the exploration.

| Resource (one per pool child, L1) | notify | transcribe |
|---|---|---|
| SQL engine, pool 5 | yes | yes |
| Redis client, `client_name` `worker-notify` / `worker-transcribe` | yes | yes |
| `CeleryJobQueue` | yes | yes |
| aiogram `Bot` session and `AiogramUserNotifier` (an `UnconfiguredNotifier` raising `NotificationError` without a token) | yes | yes (retry edit) |
| `AiogramVoiceFileSource` (an `UnconfiguredVoiceSource` raising `VoiceFileUnavailableError` without a token) | no | yes |
| `RedisEventPublisher` | no | yes |
| extractor, `open_extractor(deadline_seconds=30, interrupts=(SoftTimeLimitExceeded,))` | no | yes |
| transcriber, `open_transcriber(settings)` | no | yes |
| use cases | `NotifyUser`, `RecoverStuckVoiceJobs` | `TranscribeVoiceJob` with its `CreateTasksFromMessage` and `RegisterOrGetUser` |

Without a Telegram token a transcribe job retries its download five times and ends `transient_exhausted`, and its notification ends `given_up`: S3-Y1 accepted a token-less worker with a warning. ### 3.10 Celery tasks and the schedule (S5.4)

## 8. Risks

- The OpenAI error codes for quota (`insufficient_quota`) and for a bad file come from the SDK and its documented shapes; the single live call proves only the success path.
- The whisper-server error bodies are undocumented strings of 1.9.4; a newer server (the Compose image in S8) may word them differently, and the conversion failure then becomes a retried 500.
- Synthetic Russian speech measures timing, not accuracy.
- A soft limit that lands inside S4's download or notifier is rewritten as their error; the 400 s budget fires first in every normal path, so this needs an attempt already 20 s past its budget.
- Without a Telegram token the worker retries downloads it cannot do and the ack stays "Transcribing…"; this needs the bot and the workers to read different settings (3.9); accepted under S3-Y1.
- Whisper can turn silence or noise into a fluent phantom phrase ("Thank you.") or a repetition loop; both become a task. Only bracketed non-speech markers count as empty; V12 accepts the loop.
- A worker that writes `too_long` against a database still at `0003` fails the write; the row stays `processing`, the sweep retries it, and after five attempts the user gets the generic text. The rollout order (migrate before the workers) is S8's (`migrate` runs first) and `yarn db:migrate` in development; the worker has no schema check, because S3's harness starts workers against a closed database port.
- A deterministic database error in uow B (none is known: domain validation precedes every write) would repeat the paid provider call on each of the five attempts before `stuck`.
- whisper-server finishes an abandoned inference behind its mutex (unverified for 1.9.4); after one 300 s timeout the next job may wait behind it and time out too.
- Two copies of one notification (a sweep copy beside a slow original) can both send on the reply path (edits are idempotent); a crash between the uow B commit and `publish_events` loses that `task.created` until the dashboard's next reconnect (umbrella 3.4).
- A soft limit that lands before the claim commits is not recorded; the sweep re-runs the row.

## 1. Problem

The owner asked on 2026-10-27: «Надо в зонтик добавить, чтобы в боте еще по команде tasks показывались актуальные задачи». Today the bot answers `/tasks` in a private chat with the unknown-command reply, and the only way to see tasks is the dashboard link from `/dashboard`, which rotates the token and signs out other devices (S4 row B10). S10 adds a read-only command that lists the user's current tasks as one plain-text message. Changing and deleting tasks stay on the dashboard.

### 3.2 `ListCurrentTasks`

```python
CURRENT_TASKS_LIMIT = 15


@dataclass(frozen=True, slots=True)
class CurrentTasks:
    in_progress: tuple[Task, ...]
    pending: tuple[Task, ...]
    more: bool


class ListCurrentTasks:
    def __init__(self, list_tasks: ListTasks) -> None:
        self._list_tasks = list_tasks

    async def execute(self, user_id: int) -> CurrentTasks:
        in_progress = await self._list_tasks.execute(
            user_id, status=TaskStatus.IN_PROGRESS, after=None, limit=CURRENT_TASKS_LIMIT
        )
        room = CURRENT_TASKS_LIMIT - len(in_progress.items)
        pending = await self._list_tasks.execute(
            user_id, status=TaskStatus.PENDING, after=None, limit=max(room, 1)
        )
        shown_pending = pending.items if room > 0 else ()
        more = (
            in_progress.next is not None
            or pending.next is not None
            or (room == 0 and bool(pending.items))
        )
        return CurrentTasks(
            tuple(item.task for item in in_progress.items),
            tuple(item.task for item in shown_pending),
            more,
        )
```

- The use case always makes exactly two `ListTasks` calls, so `page_for_user` runs twice: first with `fetch=16`, then with `fetch=room + 1` (at most 16, and 2 when `room` is 0). When 15 or more tasks are `in_progress`, the `pending` call with `limit=1` only learns whether a pending task exists; that item is not shown. For exactly 15 `in_progress` tasks it is the only source of `more`; for 16 or more, `in_progress.next` already sets it. The reads total at most 18 rows (16 + 2); 16 + 16 cannot happen, because a full pending fetch needs an empty `in_progress` group.
- `ListTasks` is the only listing path (umbrella section 18): no new repository method. Each `ListTasks.execute` opens and closes its own unit of work. `page_for_user` also returns each task's source text; `ListCurrentTasks` drops it, and the reply never shows it.
- The order inside each group and the status filter come from `page_for_user`; `tests/contract/test_task_paging.py` already checks both, against the fake store and real PostgreSQL (`test_status_filter_is_kept_across_all_pages`).
- The two calls are separate snapshots. A status change between them can show a task twice or omit it, with no more-line, in that one reply; the next `/tasks` is correct. Accepted at this scale (section 8).

### 3.3 Texts (`application/replies.py`)

`current_tasks_text` builds, for the non-empty case (lines joined by `\n`):

```
Your current tasks:

In progress:
- <title>
...

Pending:
- <title>
...

More tasks on your board: /dashboard
```

An empty group and its blank line are omitted; the more-line appears only when `more` is true. With no task in either group it returns `NO_CURRENT_TASKS`:

```
You have no current tasks. Send a text or a voice message to create one.
```

Changed S4 texts (S10-D5; departure P1):

```
START:
Send me a text or a voice message and I will turn it into a task.
/tasks – your current tasks.
/dashboard – a private link to your task board.
Transcription: {provider}. Task extraction: {extractor}.

UNKNOWN_COMMAND:
Unknown command. Send a text or a voice message to create a task; /tasks lists your current tasks, /dashboard opens your board.
```

The en dash in `START` keeps the existing `# noqa: RUF001 - Owner-approved copy.` comment.

**The 4096 limit.** A title is one line (`clean_inline`) of at most `TITLE_MAX = 120` code points, so at most 240 UTF-16 code units, which is how Telegram counts the limit. The worst case, computed for every split of the 15 lines between the two groups with titles of 120 astral-plane characters, is 3726 units (both groups present), below 4096. One group alone gives 3712 (`Pending` only) or 3716 (`In progress` only). The cap of 15 therefore guarantees the limit without measuring. Criterion C5 checks the both-groups worst case. Its titles are 120 astral-plane alphanumeric characters (`"𝐀" * 120`), because `MessageText.parse` refuses text without an alphanumeric character, so emoji-only text cannot become a task. The length is measured as `len(text.encode("utf-16-le")) // 2`.

**Lint.** `ruff` (RUF001) flags each line with an en dash, so the new `START` line carries its own `# noqa: RUF001 - Owner-approved copy.`. The new `UNKNOWN_COMMAND` is longer than the 100-character line limit and is written as implicit string concatenation, byte-identical to the text above.

### 3.4 The handler

```python
async def handle_tasks(message: Message, ports: BotPorts) -> None:
    user = await ports.register.execute(identity(message))
    current = await ports.list_current_tasks.execute(user.user.id)
    await reply(message, ports, replies.current_tasks_text(current))
```

- Routing: `router.message.register(handle_tasks, F.text, Command("tasks"))`, placed after `handle_dashboard`. In a group, `handle_nonprivate` answers first with `NOT_PRIVATE` (S4-Z4), unchanged. `/tasks@<this bot>` is matched by `Command`; arguments after `/tasks` are ignored. A voice with the caption `/tasks` stays a voice (`F.text`, as for `/dashboard`).
- L2: `RegisterOrGetUser.execute` and both `ListTasks.execute` calls each commit or close their unit of work before `reply` runs. The existing `FakeUserNotifier` asserts `not inside_unit_of_work.get()` on every reply, so every handler test checks L2.
- L3: the use cases use the `uows` factory the bot already builds; no new engine or client.
- Errors: a database failure raises into the existing error hook, which answers `SOMETHING_WENT_WRONG` (S4). A failed reply is logged by `reply` as today. No event is published: the command changes nothing visible on the dashboard (registering a first-time user publishes nothing today either).

### 3.5 The command menu (S10-D6)

`BOT_COMMANDS` in `entrypoints/bot/__init__.py`:

| command | description |
|---|---|
| `start` | `How to use this bot` |
| `tasks` | `Your current tasks` |
| `dashboard` | `A private link to your task board` |

In `_open_resources_and_run`, after the existing `bot.me()` and `bot.delete_webhook(...)` block, the bot calls `await bot.set_my_commands(BOT_COMMANDS)` inside its own `try`. `AiogramError`, `TimeoutError` and `ClientError` are logged at WARNING with the exception type only, and start-up continues to polling; cancellation propagates. The call runs once per start, after the polling lock is held, with `scope=BotCommandScopeAllPrivateChats()`, so the menu does not appear in groups, where every command answers `NOT_PRIVATE`. It uses the existing `Bot` session with `request_timeout=10`, as the notifier does, so a stalled call delays polling by at most 10 s instead of aiogram's default 60 s.

## 8. Risks

- Two snapshots (section 3.2): a status change between the two `ListTasks` calls can show one task twice or omit it in that one reply. The next `/tasks` is right. Accepted: one transaction for both reads would need a new composable `within` on `ListTasks`, which no other caller needs.
- A `/tasks` sent while a text is still being extracted (up to 8 s) or a voice is still being transcribed answers `NO_CURRENT_TASKS` or omits that task, because the task does not exist yet; the `Task created: …` reply follows. The empty text stays true at that moment.
- The more-line and the empty text name `/dashboard`, which Telegram shows as a tappable command; tapping it issues a new link and signs out other devices, and its own reply says so (S4 row B10). The existing `UNKNOWN_COMMAND` already points to `/dashboard` the same way.
- `setMyCommands` changes the bot's profile on Telegram at every start. The test bot keeps its token (umbrella section 18), so the menu stays set between runs; it is the same three commands each time.
- A first-time user who only sends `/tasks` now gets a user row, as with `/dashboard`.

# S1 — Skeleton, tooling and local infrastructure

> **STATUS 2026-10-24: ACTIVE — stage design, round 2 (gate round 1 findings G1, G2 folded in; section 11), for the design gate.**

Stage S1 of the umbrella design `docs/plans/2026-10-23-umbrella-assessment.md` (umbrella section 5, S1). The umbrella fixes the scope; this document fixes how S1 delivers it, records the owner's decisions for this stage, and lists where S1 departs from the umbrella's text. "Umbrella x.y" names a section of the umbrella design; a bare number names a section of this document. The implementation steps of this stage are called S1.1 to S1.5 to keep them apart from the umbrella's stages S1 to S9.

## 1. Problem

The repository holds only guides and the umbrella design. Every later stage needs the same ground: a Python project and a TypeScript project with their checks, one verification command that fails on a broken rule, local PostgreSQL and Redis, a backend image that builds and starts, and a way to start the owner's local transcription server. S1 builds that ground and no product behaviour.

### 3.3 Root commands

Root `package.json` scripts. Python tools run as `uv run --locked --directory backend <tool>`: the working directory becomes `backend/`, so paths inside Python commands are relative to `backend/`, and `--locked` fails when `uv.lock` does not match `pyproject.toml` instead of rewriting it.

| Command | S1 behaviour |
|---|---|
| `verify` | `check:size` → `check:scripts` → `verify:backend` → `api:check` → `verify:frontend`; stops at the first failure |
| `verify:backend` | `uv lock --check` → `ruff check .` → `ruff format --check .` → `mypy` → `lint-imports` → `pytest -m "not integration"` → `pytest -m integration` |
| `verify:frontend` | `yarn workspace frontend run verify`: `eslint .` → `prettier --check .` → `tsc -b` → `vitest run` |
| `check:scripts` | `node --test scripts/` and `prettier --check --config frontend/.prettierrc.json scripts` |
| `test:unit` | `pytest -m "not integration"` and `vitest run`, for work without the stack |
| `check:size` | `node scripts/check-file-size.mjs` |
| `api:schema` | `uv run … python -m taskbot.entrypoints.api.export_schema openapi.json` (lands in `backend/openapi.json`), then `yarn workspace frontend run api:generate` |
| `api:check` | `node scripts/check-api-schema.mjs` |
| `infra:up` | `node scripts/infra.mjs up`: the guard of 3.6, then `docker compose up -d --wait postgres redis` |
| `infra:stop` | `node scripts/infra.mjs stop`: the guard, then `docker compose stop` (containers and data stay; 3.6) |
| `dev:api` | `uvicorn --factory taskbot.entrypoints.api.app:create_app --reload --port 8000` |
| `dev:web` | Vite dev server on 5173 (`strictPort`); `/api` proxied to `http://127.0.0.1:8000` with the prefix unchanged |
| `dev:whisper` | `node scripts/dev-whisper.mjs` |
| `db:migrate`, `dev:seed` | stub → "built in S2" |
| `dev:worker <role>` | stub → "built in S3" (role `transcribe` or `notify`) |
| `dev:bot` | stub → "built in S4" |

`verify` needs `yarn infra:up` first; the integration half says so when the stack is down (3.5). A stub writes `yarn <command> is not available yet: it is built in stage <stage>.` to stderr and exits 1; the stage that builds the command replaces one line of `package.json`. Yarn 1 hoists the frontend's tools into the root `node_modules`, so root scripts can call `prettier`.

**`check-file-size.mjs`** runs at the repository root, lists files with `git ls-files -z --cached --others --exclude-standard`, keeps regular files only (`lstat`; missing, deleted or symlinked paths are skipped), counts newline characters of `*.py`, `*.ts`, `*.tsx`, `*.mjs`, `*.css`, exempts tests (`tests/`, `*.test.*`, `src/test/`), generated files (`src/api/generated/`, `openapi.json`) and Alembic versions, and fails listing every file over 700 lines with its count.

**`check-api-schema.mjs`**:
1. Exports the schema to an absolute temporary path and compares it byte for byte with `backend/openapi.json`. The exporter writes `json.dumps(app.openapi(), indent=2, sort_keys=True) + "\n"`.
2. Runs the generator from that temporary schema into `frontend/.api-check/` (inside `frontend/`, so the generator's Prettier step finds `frontend/.prettierrc.json`; measured: an output directory outside `frontend/` or under `node_modules` is formatted with default options and never matches). `frontend/.api-check/` is git-ignored, Prettier- and ESLint-ignored, excluded from `tsc` and from the size check, and removed in a `finally` block. The generator config reads `SCHEMA_IN` / `SCHEMA_OUT`, with the committed paths as defaults.
3. Compares file lists and bytes of `frontend/.api-check/` with `frontend/src/api/generated/`.

Either mismatch fails with `<path> is stale; run yarn api:schema`.

**Script tests** (`scripts/*.test.mjs`, `node --test`, temporary directories as fixtures): the size check passes 700 lines and fails 701, exempts a 900-line test file and a generated file; the schema check passes on a clean tree and fails naming the path when either the schema or a generated file differs; the stub exits 1 naming its stage; `lib/env.mjs` reports a missing `.env` with one line; the stack guard's decision function (3.6) refuses each forbidden combination and allows the default and a valid isolated stack. The scripts are plain ESM run by Node, outside the TypeScript project; they are formatted by Prettier and tested, not type-checked (a recorded exception to AGENTS.md's typecheck rule: five small scripts do not earn a separate `tsconfig` and typed lint setup).

### 3.4 Backend

- **Build.** `[build-system] requires = ["uv_build>=0.13,<0.14"]`, `build-backend = "uv_build"`; module `taskbot` under `src/`. Without a build system `uv sync` does not install `taskbot` (measured). `uv sync` runs after `src/taskbot/` exists; an earlier sync installs an empty project and `lint-imports` then fails to find `taskbot` until `uv sync --reinstall-package taskbot`.
- **Layers.** `domain`, `application`, `infrastructure`, `entrypoints` exist from S1, so the two import-linter contracts of umbrella 3.3 are checked from the first commit, copied verbatim, with `root_package = "taskbot"` and `include_external_packages = true`.
- **ruff.** `line-length = 100`, `target-version = "py314"`; `select = ["E", "W", "F", "I", "N", "B", "UP", "ASYNC", "SIM", "PT", "RUF", "C901", "PLR0912", "PLR0915"]`; `max-complexity = 10`, `max-branches = 12`, `max-statements = 40`.
- **mypy.** `strict = true`, `plugins = ["pydantic.mypy"]`, `files = ["src", "tests"]`; `[tool.pydantic-mypy] init_typed = true, init_forbid_extra = true, warn_required_dynamic_aliases = true` (without them the generated `__init__` accepts `Any` and unknown keyword arguments; measured). An override that silences a library is added only if mypy reports it, with a comment saying why.
- **pytest.** `asyncio_mode = "auto"`, `testpaths = ["tests"]`, `addopts = "--strict-markers"`, marker `integration`.
- **Settings** (`taskbot/infrastructure/settings/`). `BaseAppSettings(BaseSettings)`: `env_file` = the repository root `.env`, as an absolute path computed from the module location (in a source checkout that is the repository root whatever the working directory; in the image the file does not exist and the environment alone applies), `extra="ignore"` (one `.env` serves every entry point), `env_ignore_empty=True` (an empty key becomes `None`, the degrade rule of umbrella 3.7), field `log_level`. `ExtractorSettingsMixin` is a plain `pydantic.BaseModel` with `task_extractor: Literal["heuristic", "claude"] = "heuristic"`, `anthropic_api_key: SecretStr | None = None`, `anthropic_model: str = "claude-haiku-5-5"`. It must not be a `BaseSettings`: measured, with the order `class X(BaseAppSettings, Mixin)` a `BaseSettings` mixin replaces the base configuration and the `.env` file is silently ignored. Later stages declare entry-point models in that order: `BotSettings(BaseAppSettings, ExtractorSettingsMixin)`.
- **`test_settings.py`** builds a test model `class _S(BaseAppSettings, ExtractorSettingsMixin)` with `_env_file=<tmp>` and removes `TASK_EXTRACTOR`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `LOG_LEVEL` from the environment (`monkeypatch.delenv`), so the developer's own `.env` or shell cannot change the result. It asserts: values from the file reach the mixin fields; `ANTHROPIC_API_KEY=` becomes `None`; `TASK_EXTRACTOR=gpt` fails with a validation error naming the field `task_extractor`.
- **`test_env_example.py`** (added in S1.2, with `.env.example` and `InfraTestSettings`, which it needs) reads `.env.example` through `BaseAppSettings`-derived models of S1 (`_S` and `InfraTestSettings`) and asserts that every key whose name ends in `_TOKEN` or `_KEY` is empty. Later stages add their models to this test, so `.env.example` cannot drift from the settings.
- **API.** `entrypoints/api/app.py`: `create_app() -> FastAPI` with `GET /health` returning `Health` (`status: Literal["ok"]`), public, at the root (umbrella 3.1 probes `/health`; product routes from umbrella S6 on live under `/api`). Response models set `model_config = ConfigDict(json_schema_serialization_defaults_required=True)`, so defaulted fields are required in the generated response types. `export_schema.py` takes the output path as its only argument.

### 3.5 Integration tests fail loudly

- `tests/integration/conftest.py` marks every item under `tests/integration/` with `integration` (`pytest_collection_modifyitems`), and a `trylast` `pytest_collection_finish` hook runs only when an integration item is selected. It opens a TCP connection (2 s timeout) to the host and port of `DATABASE_URL` and `REDIS_URL` (defaults 5432 and 6379 when the URL has no port) and, if either fails, calls `pytest.exit` with return code 2 and `PostgreSQL at <host>:<port> is unreachable: run yarn infra:up` (or the Redis equivalent). Nothing is ever skipped.
- `tests/integration/settings.py`: `InfraTestSettings(BaseAppSettings)` with `database_url` and `redis_url`, defaults equal to the `.env.example` development values, so a missing `.env` still gives the reachability message, not a validation trace.
- `test_infrastructure.py` proves the credentials, not only the port: `SELECT current_database(), current_setting('server_version_num')` through asyncpg (the `+asyncpg` suffix stripped), asserting the database name and major version 18; `PING` through redis-py. It only reads (R-ISO).

### 3.6 Local infrastructure and its lifecycle

`docker-compose.yml`, top-level `name: ${TASKBOT_STACK:-taskbot}`, two services. The shared project's service definitions contain exactly two variables, the host ports `TASKBOT_PG_PORT` and `TASKBOT_REDIS_PORT`; everything else is a literal, and nothing comes from `env_file`. So `.env` files and shell variables of any worktree cannot change the shared definitions, except through those two ports, which the guard below refuses for the shared project. Measured with `docker compose config --hash postgres` on the probe file `.tasks/artifacts/2026-10-23-s1/g1-probe-compose.yml`: no `.env`, a `.env` setting `POSTGRES_PASSWORD`/`POSTGRES_PORT`/`POSTGRES_USER`, and a shell `POSTGRES_PORT` all give the same hash and project `taskbot`; `TASKBOT_PG_PORT=5433` changes the hash; `TASKBOT_STACK=taskbot-alt` with its own ports gives project `taskbot-alt` with its own volumes.

- `postgres`: `postgres:18-alpine`; `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` are the literal development value `taskbot` (not secrets: they are already public in `.env.example`, and the port is bound to 127.0.0.1); named volume `postgres-data:/var/lib/postgresql` (the image's data root since 18); health check `pg_isready -h 127.0.0.1 -U $$POSTGRES_USER -d $$POSTGRES_DB`, interval 2 s, retries 30, start period 5 s — `-h` matters: without it the probe uses the Unix socket, which the image's temporary init server opens before TCP, and `--wait` can return early (measured); port `127.0.0.1:${TASKBOT_PG_PORT:-5432}:5432`.
- `redis`: `redis:8`; volume `redis-data:/data`; health check `redis-cli ping`; port `127.0.0.1:${TASKBOT_REDIS_PORT:-6379}:6379`.
- No restart policy. Umbrella S8 adds the other services; the `postgres` and `redis` definitions change only through a design decision, because any byte of difference makes one worktree's `up` recreate the stack under the others.

**Shared-stack guard** (`scripts/infra.mjs up|stop`). It loads `.env` the way Compose reads it for interpolation (shell values win) and decides before calling Docker:

| `TASKBOT_STACK` | Ports (`TASKBOT_PG_PORT`, `TASKBOT_REDIS_PORT`) | Decision |
|---|---|---|
| unset or `taskbot` | unset or 5432 / 6379 | the shared stack: run Compose |
| unset or `taskbot` | any other value | refuse, exit 1: `The shared stack taskbot uses ports 5432 and 6379. For other ports set TASKBOT_STACK=taskbot-<name> (its own containers and volumes).` |
| `taskbot-<name>` | both set, neither 5432 nor 6379 | an isolated stack: run Compose |
| `taskbot-<name>` | unset or a default port | refuse, exit 1: an isolated stack needs its own ports |
| any other name | — | refuse, exit 1: the name must start with `taskbot-` |

The decision is a pure function in `infra.mjs`, tested by `scripts/infra.test.mjs`. `DATABASE_URL` and `REDIS_URL` in `.env` must follow the ports of the stack in use; `.env.example` says so. The guard covers the commands of this repository; calling `docker compose` directly bypasses it, and the README and both module guides say to use `yarn infra:up` and `yarn infra:stop`. A password cannot drift: it is a literal.

**Lifecycle rule (S1-D7).** The stack belongs to the owner's machine, not to a stage. Stages start it with `yarn infra:up` and leave it running; no stage runs `docker compose down` or deletes its volumes as cleanup. `yarn infra:stop` stops it without removing anything. Umbrella S8's fresh-clone run is an isolated stack (`TASKBOT_STACK=taskbot-e2e` with its own ports), so it never touches the shared stack. Development servers of every worktree share the one `taskbot` database and Redis: one person's development data on one machine.

`.env.example` lists every variable of umbrella 3.7 with its development value except `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB` (literals in Compose; `DATABASE_URL` carries the credentials), plus `TASKBOT_STACK`, `TASKBOT_PG_PORT` and `TASKBOT_REDIS_PORT` commented out, with the note that `DATABASE_URL` and `REDIS_URL` must follow the ports; secrets empty (`TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`); `WHISPER_DEV_MODEL_PATH` as an absolute placeholder (no `~`, no `$`: three different parsers read this file). `API_PORT` and `WEB_PORT` are listed for umbrella S8 and not read in S1.

`.gitignore` additions (in S1.1, before the first Python run): `__pycache__/`, `*.pyc`, `.venv/`, `*.tsbuildinfo`, `.vite/`, `frontend/dist/`, `frontend/.api-check/`, `.env.*` with `!.env.example`.

### 3.7 Backend image (smoke build)

`docker/backend.Dockerfile`, after the uv Docker guide: a builder stage on `python:3.14-slim` with `COPY --from=ghcr.io/astral-sh/uv:0.13.5 /uv /bin/`, `UV_COMPILE_BYTECODE=1`, `UV_LINK_MODE=copy`, `UV_PYTHON_DOWNLOADS=0`; a dependency layer `uv sync --locked --no-dev --no-install-project`, then the project `uv sync --locked --no-dev --no-editable`; a runtime stage on `python:3.14-slim` with the copied `/app/.venv` on `PATH`, a non-root user, and, as that user, `RUN python -c "from taskbot.entrypoints.api.app import create_app; create_app(); import celery, aiogram, openai, anthropic, sqlalchemy, asyncpg, alembic, redis, httpx"`. `CMD` is exec form with `python` as PID 1 (`python -m uvicorn --factory taskbot.entrypoints.api.app:create_app --host 0.0.0.0 --port 8000`); umbrella S8 sets each service's command. No model runtime, no ffmpeg.

`.dockerignore` excludes with recursive patterns: `**/.env`, `**/.env.*` (keeping `!**/.env.example`), `**/.venv`, `**/node_modules`, `**/__pycache__`, `**/.mypy_cache`, `**/.ruff_cache`, `**/.pytest_cache`, `.git`, `.tasks`, `.agent-collab`, `source`, `REQUIREMENTS.md`, `frontend`.

`backend/AGENTS.md` states the rule that keeps the image from rotting before umbrella S8: a stage that adds a dependency or a top-level directory under `backend/` (for example `alembic/`) re-runs the smoke build and records it.

### 3.8 Local transcription server

`scripts/lib/env.mjs` loads the root `.env` resolved from the script's own location (not the working directory) with `process.loadEnvFile`; a missing file gives one line, `.env not found: copy .env.example to .env`, and exit 1. Variables already set in the shell win (Node's behaviour, stated in the README).

`scripts/dev-whisper.mjs` checks that `whisper-server` and `ffmpeg` are on `PATH` and that `WHISPER_DEV_MODEL_PATH` names an existing file (a leading `~` is expanded by the script), and otherwise exits 1 with one line naming what is missing. Then it runs `whisper-server -m <model> --host 127.0.0.1 --port 8178 --convert -l auto` with inherited output and forwards `SIGINT`, `SIGTERM` and `SIGHUP` to the child, so stopping `yarn dev:whisper` frees port 8178. `-l auto` matters: the server's default language is English.

`backend/tests/fixtures/voice-en.ogg`: one English sentence of synthetic speech made on macOS with `say` and converted with `ffmpeg -c:a libopus -b:a 16k -ac 1 -application voip`; about 7 KB, 3–4 s, no real chat content. `fixtures/README.md` records both commands and the sentence. Umbrella S5 reuses it or adds its own longer fixtures.

### 3.9 Frontend

- **Project.** Vite + React + TypeScript as a Yarn workspace (`"private": true`, `"version": "0.0.0"`; Yarn 1 ignores a workspace without a version). `tsconfig.json` references `tsconfig.app.json` (`src`) and `tsconfig.node.json` (`vite.config.ts`, `openapi-ts.config.ts`, `eslint.config.js`). ## 6. Rule for later stages: integration tests isolate themselves (R-ISO)

All stage worktrees share one PostgreSQL and one Redis (S1-D7). Therefore:

1. **PostgreSQL.** An integration-test session creates its own database named `taskbot_test_<unix-time>_<random>`, applies the migrations or schema to it, and drops it at the end. At start it drops databases with that prefix whose time part is older than six hours (`DROP DATABASE … WITH (FORCE)`), so a killed session does not leave databases behind and a live parallel session is never touched. No test writes to the `taskbot` database. Umbrella S2 builds this fixture.
2. **Redis.** A session uses a unique prefix for everything it names: keys, pub/sub channels, locks (for example the bot's polling lock) and Celery queues (kombu's `global_keyprefix`, or per-session queue names), and deletes its keys at the end. Umbrella S3 builds this fixture and names the mechanism.
3. No test assumes it is alone on the stack. S1's own integration test only reads.
